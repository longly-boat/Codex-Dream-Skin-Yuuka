# Codex Dream Skin Yuuka v1.9.3

[中文](https://github.com/longly-boat/Codex-Dream-Skin-Yuuka/blob/v1.9.3/docs/releases/v1.9.3.md) · **English**

v1.9.3 fixes two cases where the stock taskbar entry or login startup could fail to load the theme: contention for the startup operation lock, and a saved injector process ID being reused by another program after Windows restarts.

## Fixes and improvements

- **Retry temporary startup lock contention.** If tray initialization or another operation briefly holds the lock, automatic takeover now retries only a token-validated busy result received before the launcher first acquires the lock. There are at most four attempts within a 90-second retry scheduling budget. No delay is added when the lock is available; retries stop when the budget is exhausted.
- **Keep the single-restart protection.** Attempts retain the same reservation and revalidate the original Codex process. A failure after acquiring the lock or starting takeover is not retried as lock contention. Stop, pause, and identity checks remain effective. This is neither an unlimited restart loop nor restart-free injection.
- **Recognize a reused injector PID.** A valid saved UTC creation time that differs from the current process creation time proves the old record is stale. The unrelated process is preserved. Missing, malformed, or unverifiable timestamps still fail safely; a PID alone is never authority to terminate a process.
- **Improve diagnostics and regressions.** Logs now include launcher lock waits, tray initialization time, and deferred attempts. Added tests cover a real contended lock, forged or malformed results, stop/pause controls, and PID reuse.

## Upgrade and use

This release provides a **Windows x64** installer only. Download `CodexDreamSkinYuuka-Setup-v1.9.3.exe` and the matching `SHA256SUMS.txt`, verify the checksum, and run Setup. The installer is **not code-signed**, so Windows may show an unknown-publisher or SmartScreen prompt.

To upgrade from Yuuka v1.9.2, save your input, quit Codex, and install into the existing Yuuka directory. Setup preserves themes and preferences and restores the previous automatic-takeover setting. Daily Plan continues to use the existing Codex local storage; this upgrade does not clear it. If automatic takeover was not enabled, enable it in the theme manager before using the stock taskbar entry.

The stock Store entry still starts Codex first, after which the theme tool closes that instance and restarts it once. This update improves reliability without promising a fixed startup time on every device. Official Codex installation files are not modified.

For first installation or migration from an earlier custom build, see the [Windows installation guide](https://github.com/longly-boat/Codex-Dream-Skin-Yuuka/blob/v1.9.3/docs/install-windows.en.md) and [usage and migration guide](https://github.com/longly-boat/Codex-Dream-Skin-Yuuka/blob/v1.9.3/YUUKA-README.md). macOS/Linux receive version alignment only, with no Yuuka packages released. The independent companion pet is not repackaged in this update.
